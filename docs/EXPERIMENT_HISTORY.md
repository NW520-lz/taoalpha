# 实验与历史清单的只读核验

`inspectExperimentHistory(db, registry, {experimentId, version, expected})` 是内部只读接口，调用方必须提供与 `db` 同一连接的进程内 `createExperimentRegistry` 实例；不得从不可信请求构造此依赖。它在 SQLite 读取事务中读取登记与历史清单，不修改登记或清单；表不存在、内容损坏、引用或哈希不匹配时拒绝。返回固定错误，不回显原始异常。

接口核对登记中冻结的数据引用 `history_<sha256>`、正文哈希、解析版本和探索、验证、评价窗口是否包含在清单的请求范围内；检查清单记录的站点、标的、产品和周期是否与显式 `expected` 相符；检查原始响应正文与其中记录的哈希，并显示清单自报的 K 线覆盖、全部缺口、来源失败数量、资金费状态和未知项。清单中的来源正文不返回。登记内容和清单不被修改。

**站点、产品、标的、周期在现有登记中没有冻结。** `expected` 只是调用方提供的比较条件，结果标记 `caller_supplied_unbound`；不得据此称这些字段已通过预登记绑定。后续需要新版本契约冻结这些条件并绑定范围。清单请求覆盖窗口不证明 K 线存在或完整；覆盖状态和缺口来自清单自身，不独立重算全部历史。可获知时间、历史标的池、来源真实性和数据完整性仍未知。即使清单声称 K 线完整或来源成功，结果始终 `unvalidated`、`executionAuthorized: false`，不代表回测成功、模拟通过或实盘准入。

无清单时不触发历史模块的惰性建表；不联系交易所或账户。本接口不提供历史重新采集、策略评价、交易或凭证操作。哈希只能检查数据一致性，不能防御拥有相同操作系统与数据库权限的恶意进程；没有可信时间戳，也不能证明事前登记。

缺口列表按清单原样返回，不以固定数量截断；它来自受信任的内部采集流程，调用方应控制采集输入和响应规模。数据库故障或登记存储不可用返回固定的 `PERSISTENCE_UNAVAILABLE`，无效请求和匹配失败返回 `INVALID_INPUT`，不泄露底层错误。
