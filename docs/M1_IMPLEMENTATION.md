# M1：风控与 OKX 模拟执行开发记录

更新：2026-10-28。M1 尚未完成。此页记录已落地的代码边界和后续接入顺序，不构成任何账户或模拟订单验收。

## 已实现的内部基础

- `src/risk/loss-ledger.ts`：登记不可变的账户范围基准与风险策略哈希，记录带交易所引用的已核对入出金，以及逐次账户净值观察。损益按 `当前净值 + 已核对出金 - 已核对入金 - 初始净值` 用十进制计算；只有基准之后、观察时点之前的资金事件参与该次计算。
- `src/store/schema.ts`：损失范围、资金事件、净值观察和触线事件各自持久化；UPDATE/DELETE 由触发器拒绝。相同来源重复提交返回原结果，内容冲突报错；观察时间必须前进。
- 观察数据不完整时，输出缺少的核对项并阻止新增风险；不会凭不完整输入捏造触线。触及配置中的提醒、暂停、硬停止三层门槛时分别记录事件；直接跨到高档位时同时保存历史事件并优先展示高档位待处置动作。反弹和重启不解除已有锁。
- `test/risk/loss-ledger.test.ts` 使用合成数据检查阈值边界、入出金、未来资金事件、数据缺失、重复输入、跨范围隔离及重启持久性。`test/store/multi-process.test.ts` 验证两个 Node 进程共享 SQLite 文件的写锁和唯一键前提。

这里的 `blockNewRisk: false` 只表示损失账本本身未发现阻断，**绝不等于允许下单**。策略准入、账户实况、预算、产品能力、可信批准及提交前重检尚未完成。`requiredActions` 是待处置事项，不会自动发 OKX 请求。当前只用合成数据调用内部函数，尚无账户凭证、OKX demo、CLI/MCP 写入入口或人工恢复接口。

## 后续顺序与准入证据

| 顺序 | 工作 | 完成时必须拿到的证据 |
| --- | --- | --- |
| 1 | 可信账户只读适配器与资金流水对账；核对基准、站点、模式、产品、余额、仓位、订单 | 实际账户读取、差异报告、脱敏引用；不明时禁止新增风险 |
| 2 | 由可信人工入口确认并版本化风险配置；将损失账本接入账户刷新和启动恢复 | 真实用户动作绑定配置哈希；只读查询能显示重启后的全部未解决锁 |
| 3 | 预算、名额、同币合并敞口、止损距离及含成本计划损失的确定性计算 | 现货/合约单位、精度取整、在途与未知订单占用的合成边界测试 |
| 4 | 交易卡编译与可信逐卡批准；策略验证不足仍不能形成实盘卡 | 卡片哈希、环境/账户绑定、止盈止损和异常授权、伪造批准拒绝 |
| 5 | 同事务消费批准、预留、持久执行意图和稳定子动作 ID | 双客户端、崩溃、重放、数据库故障下的唯一意图证据 |
| 6 | 固定版本的 OKX Trade Kit 执行适配器，先只接 demo，并核验逐仓、自动追加、保护方式 | 真实 demo 的现货与永续订单、成交、止损/止盈 ID 和能力差异 |
| 7 | 未知结果、部分成交、保护失败、暂停/硬停止触线的受限处置与对账 | 真实 demo 与故障注入证据；结果未知时不重发增险单，不误动旧仓 |

每一步都沿用 [不可破坏约束](INVARIANTS.md) 和 [验收映射](EVALS.md)。历史验证、模拟闭环及独立实盘准入仍是不同门槛；M1 完成也不会自动开放实盘。
