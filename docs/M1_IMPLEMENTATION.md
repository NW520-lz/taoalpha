## 已实现的内部基础

- `src/risk/loss-ledger.ts`：登记不可变的账户范围基准与风险策略哈希，记录带交易所引用的已核对入出金，以及逐次账户净值观察。损益按 `当前净值 + 已核对出金 - 已核对入金 - 初始净值` 用十进制计算；只有基准之后、观察时点之前的资金事件参与该次计算。
- `src/store/schema.ts`：损失范围、资金事件、净值观察和触线事件各自持久化；UPDATE/DELETE 由触发器拒绝。最新观察的相同来源重复提交在状态未变时返回原结果，内容冲突报错；若已有较新观察或新增风险事件，旧观察重放返回 `DATA_NOT_READY`，不能将历史结果作为当前风险状态。观察时间必须前进。
- 资金事件补录时间不晚于该范围最新净值观察时，数据库在同一事务保存事件并建立持久对账锁；新版观察和重放均返回 `DATA_NOT_READY`，其他已确认资金事件仍可登记。该锁无自动解除或恢复入口，既有基准和风险事件不变。迁移前的账本未记录跨表写入顺序，因此升级时将已有资金事件与最新观察时间重叠的范围保守锁定，即使当时记录顺序可能正确；没有重叠的范围不因迁移而锁定。
- 如果已有资金事件发生时间晚于或等于某净值观察，该观察无论是新提交还是重放均返回 `DATA_NOT_READY`；观察时间必须严格晚于所有已知资金事件才可计算当前账本状态。时间戳相同时先后顺序无法证实，不自动认定资金已反映在净值中。过去已保存的净损益不会把较晚资金算进去，也不会被静默改写。数据库触发器阻止旧式写入新增不晚于已知资金事件的观察；旧程序重放已保存结果仍需停用或升级。
- 数据库触发器也会拦截旧版 v2 程序在锁存在时写入新观察，但旧程序仍可读取或重放锁定前的旧结果；必须停止或升级旧进程，不能把其输出用于准入。此前已返回或缓存在内存中的结果同样不能被撤回；未来执行器必须在自己的提交事务中重新核验最新观察、所有风险事件及此锁。锁写入失败时事件和锁一并回滚并向调用方报错；调用方必须把持久化故障当成阻断，不能忽略错误继续使用旧结果。上述锁不替代真实资金流水完整性核验，且不防拥有任意数据库写权限的恶意进程。
- 观察数据不完整时，输出缺少的核对项并阻止新增风险；不会凭不完整输入捏造触线。触及配置中的提醒、暂停、硬停止三层门槛时分别记录事件；直接跨到高档位时同时保存历史事件并优先展示高档位待处置动作。反弹和重启不解除已有锁。
- `test/risk/loss-ledger.test.ts` 使用合成数据检查阈值边界、入出金、未来资金事件、数据缺失、重复输入、跨范围隔离及重启持久性。`test/store/multi-process.test.ts` 验证两个 Node 进程共享 SQLite 文件的写锁和唯一键前提。
- `src/risk/entry-risk.ts`：计划准备阶段的纯计算，按现货币数量/合约张数向下取整，用合约面值换算基础币敞口，计算止损距离损失与费用、额外滑点、资金费成本，核对预算、关联分批风险、币种/仓位名额、逐仓、自动追加和杠杆。待成交和未知提交继续占位；同币 gross/net、两侧名义、成本和风险分别展示，估值时间不一致时阻断。`test/risk/entry-risk.test.ts` 使用合成数据验证上述边界。
- 入场风控和损失账本对外部十进制输入限制为最多 256 个字符；有限加减乘和取整使用高精度，循环小数的保证金估算向上取整。修复前建立的旧损失范围没有新计算版本标记，新代码读取或重放时阻断；旧记录原样保留，尚未实现安全重算、迁移或恢复入口。数据库触发器要求新版写入标记，与观测或资金记录同事务保存；合成测试包括独立进程使用旧式 SQL 插入被阻断，但并非完整旧版程序兼容性验收。此机制不防拥有任意数据库写权限的恶意进程。旧进程仍可能读取并返回旧结果，使用前必须停用或升级旧进程，其输出不能作为准入依据。不能通过新建范围绕过既有风险事件，未来执行协调器必须先核查全部相关旧范围。合成回归覆盖极小超额、接近档位的数量和循环除法；这不构成交易所真实保证金能力验证。
- `src/risk/demo-risk-policy.ts`：将 demo 风险配置提案与账户会话和可信确认绑定，在事务内核对并登记确认；目前仅有合成确认验证，尚未完成真实人工确认或与损失账本、交易执行接通，见 [风险配置说明](DEMO_RISK_POLICY.md)。
- `src/okx/trade-kit-demo-reader.ts`、`trade-kit-transport.ts`：已接固定版本官方 MCP 的私有 demo 只读适配器，具备工具/能力验证、账户/在途单/保护读取和分页；`npm run demo:check` 只输出脱敏状态。真实 global demo 已完成只读连接检查；验收记录另附，不代表资金对账或订单闭环通过。配置步骤见 [OKX_DEMO_SETUP.md](OKX_DEMO_SETUP.md)。
- `src/account/demo-account.ts`：账户配置、USD 权益/币种权益和 SWAP 合约张数的内部字段归一与来源/读取时效校验；拒绝未知模式、错误单位、重复/缺失数据和不完整读取。CLI 仅展示固定状态/规则及缺口。未将 USD 权益视作受管 USDT 净值，也未接入损失账本。`uTime` 仍是交易所最后更新时间，不与本机读取时间混淆。
- `src/account/demo-session.ts`：将固定 demo 站点与账户身份绑定到本机范围；身份不一致时持久锁定，成功登记待处理状态后的刷新会使其他会话的旧快照失效。此基础不确认资产归属或资金流水，仍不能下单，见 [账户会话说明](ACCOUNT_SESSION.md)。
- `src/control/confirmations.ts`：冻结确认内容和范围，持久化请求、领取、决定与一次性消费；合成测试覆盖并发、崩溃未知、过期和事务回滚。Windows 桌面系统验证适配器具备非交互探测；当前本机没有可用验证设备，尚无真实用户确认，交易入口也未接入。见 [确认边界](CONFIRMATION_BOUNDARY.md)。
- `src/control/standing-authorization.ts`（ADR-012）：常设授权的提出、经可信确认入口生效、撤销与查询。授权冻结环境、策略版本、标的、单卡损失、每日卡数、每日亏损、持仓数、风险配置版本、否决窗时长和到期时间，绑定内容哈希；须引用已登记的策略版本和同一账户范围已确认的风险配置；同一范围只认最新确认的版本；撤销不需要系统验证且永久生效；live 授权一律拒绝，直到 I-02 前提可核验。摘要不回显金额上限。合成测试覆盖确认、拒绝、过期、新版本覆盖、旧版本拒绝、撤销和伪造凭证；尚无真人确认，也未接入否决窗或交易执行。账户会话快照核对抽到 `src/account/demo-snapshot.ts`，与风险配置共用。
- `src/trade/trade-card.ts`：demo 现货做多交易卡的纯函数编译。按单卡上限与风险配置中较小者倒推数量（价格距离加双边手续费和滑点），按交易所精度向下取整后交给 `assessEntryRisk` 复核；初始止损为入场价减 k1×ATR，移动止损回调价距冻结为 k2×ATR（ADR-011），均按价格精度取整；卡片列出异常处置授权，带内容哈希与到期时间，`executable` 恒为 false。报价过期或超前、风控任一阻断（含账户未对账、最小数量、预算）时不出卡并返回规则 ID。只有 demo 环境；未通过检验的策略标为 `pipeline_test_unvalidated_strategy`。卡片尚不持久化，也未接入否决窗。
- `src/trade/veto-window.ts`（ADR-012）：授权范围内交易卡的否决窗。提交时重算卡片哈希，并逐项核对账户范围、策略版本、标的、风险配置版本、单卡计划损失、卡片到期、持仓数、当日亏损和当日卡数（被拒绝的卡不占名额），超出即 `out_of_scope` 不进窗口。只有本机展示适配器报告已展示、且仍是同一份授权时才开始计时；窗口内或展示前可拒绝，窗口结束后拒绝被拒。窗口结束时重新核对授权未撤销/未替换、卡片未过期、持仓与当日亏损未超限，失败则永久作废，全部通过才记录 `standing_authorization_veto_window` 批准。所有记录只追加。持仓数与当日亏损通过注入接口读取，尚未接入真实账户；批准尚未被执行意图消费。
- `src/trade/execution-intent.ts`（I-06、I-07、I-09）：已记录批准的卡在一个 `BEGIN IMMEDIATE` 事务内被消费为唯一执行意图，同时固定入场、初始止损、移动止损三个子动作的客户订单号（由卡片哈希和角色派生，至多 32 位字母数字，重试复用）。同一卡片重复消费或从另一个数据库连接消费都返回同一意图。所有意图在交易所对账证明最终状态之前都保持占用：`openCommitments` 按同一估值时点把它们换算为风控占用，缺少价格时阻断；`openPositions` 供否决窗读取持仓数。尚无释放路径、提交前重检或交易所写入。
- `src/account/demo-reconciliation.ts`（I-07、I-17、I-19）：把一次 demo 账户读取与本地执行意图核对的纯函数。读取不完整、存在不属于任何意图客户订单号的在途单或条件单、存在永续持仓（本范围只做现货）、上次完整对账以来有未在本地登记的转账流水（bill 类型 1）、距上次完整对账超过 7 天（流水接口只覆盖 7 天）、已提交的入场不在在途列表且未按客户订单号查询或交易所报不存在、入场已有成交而初始止损不在交易所挂着时，阻止新增风险并列出原因。现货持仓归属按意图记账：每个币种由各意图入场成交量减去以基础币计的手续费得到受管持有量，账户该币余额低于受管量即阻止（超出部分视为非受管、永不卖出）；没有阻断原因时 `accountReconciled` 为 true。止损触发卖出后余额会低于受管量而被阻止，直至接入条件单历史。已知局限：止损触发退出后会被误判为保护缺失，需读取条件单历史区分（工单 07）。读取器新增 `bills`、`fills` 两项读取（按 billId 分页）和按客户订单号查询单笔订单，只有交易所错误码 51603 视为不存在；真实 demo 已验证读取完整与 51603 判定，但新账户流水和成交为空，字段格式尚未用真实数据核对。
- `src/trade/demo-executor.ts`、`src/okx/trade-kit-demo-writer.ts`（I-04、I-07、I-08）：demo 执行器与下单连接。提交入场前重检卡片未过期、对账未阻断、报价新鲜、价格偏离卡片参考价不超过上限；先持久化提交记录再调用交易所，并记录结果（已受理/明确拒绝/未知）。同一客户订单号只发送一次：发送过但没有记录结果的视为未知，留给对账，绝不重发。入场为按基础币数量的市价买单（显式 `tgtCcy=base_ccy`）；入场受理后按实际成交量扣除以基础币计的手续费、按数量精度向下取整，挂初始止损条件单与冻结回调价距的移动止损单。下单连接要求固定版本 Trade Kit 在 demo 且具写能力，只开 spot 模块，启动方式与只读连接共用凭证隔离与 demo profile 校验；只有 OKX 数字业务码视为拒绝，传输失败或回复与请求不符一律为未知。研究入口不能访问下单连接。尚无真实 demo 下单：需要用户为 demo API Key 开启交易权限，并经常设授权与否决窗产生真实卡片（工单 08）。
- `src/trade/demo-disposition.ts` 与执行器处置动作（I-07、I-15、I-17）：`planDisposition` 按卡片批准的异常处置给出下一步：入场结果未知先按客户订单号查询、绝不重发；只有明确拒绝或交易所报不存在才释放；有持仓而初始止损不在时锁定新增风险——尚未挂则先挂保护，已受理却不再挂着则先查条件单历史（触发不等于缺失），挂单被拒或未知则撤销入场剩余部分并市价退出本意图持有量。执行器新增持久风险锁（任一锁存在即拒绝所有新入场，暂无解锁入口，恢复需按 I-15 另行确认）、按入场客户订单号撤单、按持有量向下取整市价退出（客户订单号由卡片派生），均只发送一次。条件单历史查询与自动编排循环尚未实现；尚无真实 demo 故障演练。
- `src/trade/demo-cycle.ts`、`src/demo-run.ts`（工单 08 的运行入口）：`npm run demo:run -- <setup|cycle|status|revoke> --profile taoalpha_demo --site global`。`setup` 登记管道验证策略版本，并依次提出风险配置与常设授权，各经 Windows Hello 确认、刷新账户后绑定凭证。`cycle` 对账（含入场查询与受管持有量）→ 用 BTC 4H 已收盘 K 线的 ATR 生成管道验证信号并编译卡片 → 交给否决窗 → 本机窗口显示后开始计时，拒绝/关闭/显示异常即作废 → 窗口结束结算 → 批准后消费意图、重新对账与取最新报价、提交入场 → 按客户订单号等待成交（不重发）→ 挂初始止损与移动止损 → 再对账。`status` 只输出授权与对账状态，不含金额；`revoke` 撤销当前授权。当日亏损暂按 0 传入（损失账本尚未接入，管道验证无历史退出）。真实 demo 已运行 `status`（会话绑定成功、尚无授权）；`setup` 与 `cycle` 需要用户在场按 PIN 并查看否决窗口。
- `src/mcp/research-server.ts`：复用现有研究后端提供十二项 MCP 操作，报告和方法记录以结构化内容提交，不能调用账户/交易写工具；本机 stdio 握手与合成研究流程已测试。宿主身份与角色独立性仍未核验，见 [MCP 配置](MCP_SETUP.md)。

这里的 `blockNewRisk: false` 只表示损失账本本身未发现阻断，**绝不等于允许下单**；数量与组合评估也始终返回 `executionAuthorized: false`。账户检查则固定 `blockNewRisk: true`、`reconciled: false`。策略准入、资金流水/受管范围对账、预算原子预留、完整产品能力、可信批准及提交前重检尚未完成。计算器的初始保证金是名义金额除杠杆的估算，须在执行前按实际账户核验；滑点只填写输入价格尚未包含的额外损失，避免重复计费。`requiredActions` 是待处置事项，不会自动发 OKX 请求。尚无交易写入入口或人工恢复接口。

## 后续顺序与准入证据

| 顺序 | 工作 | 完成时必须拿到的证据 |
| --- | --- | --- |
| 1 | demo 只读适配器、字段归一已接；继续资金流水、受管基准/归属、产品估值和订单保护对账 | 实际账户读取与字段校验记录、完整差异报告、脱敏引用；不明时禁止新增风险 |
| 2 | 由可信人工入口确认并版本化风险配置；将损失账本接入账户刷新和启动恢复 | 真实用户动作绑定配置哈希；只读查询能显示重启后的全部未解决锁 |
| 3 | 数量与组合计算已实现；继续接入已确认风险版本、实际账户和原子预留 | 现货/合约单位、精度取整、在途与未知订单占用的合成边界测试；提交时不可只复用旧评估 |
| 4 | 交易卡编译与可信逐卡批准；策略验证不足仍不能形成实盘卡 | 卡片哈希、环境/账户绑定、止盈止损和异常授权、伪造批准拒绝 |
| 5 | 同事务消费批准、预留、持久执行意图和稳定子动作 ID | 双客户端、崩溃、重放、数据库故障下的唯一意图证据 |
| 6 | 固定版本的 OKX Trade Kit 执行适配器，先只接 demo，并核验逐仓、自动追加、保护方式 | 真实 demo 的现货与永续订单、成交、止损/止盈 ID 和能力差异 |
| 7 | 未知结果、部分成交、保护失败、暂停/硬停止触线的受限处置与对账 | 真实 demo 与故障注入证据；结果未知时不重发增险单，不误动旧仓 |

每一步都沿用 [不可破坏约束](INVARIANTS.md) 和 [验收映射](EVALS.md)。历史验证、模拟闭环及独立实盘准入仍是不同门槛；M1 完成也不会自动开放实盘。
