# 架构决策记录

状态说明：下列决定属于**当前设计**；代码、客户端能力和 OKX 账户能力尚未验证。每项列出当时选择的理由、放弃的做法以及触发复议的条件。规则数值属于用户的私有风险配置，不在公开决策记录中写死。

## ADR-001：本地 TypeScript 后端与同一业务入口

**决定：** 第一版使用受支持的 Node.js LTS、TypeScript、本机进程与 SQLite。Codex、Claude Code 的 MCP 适配器和本机 CLI 调用同一后端业务接口。

**理由：** 用户当前手动启动客户端，本机运行能先验证研究、批准和订单闭环；统一入口避免两个客户端各自实现一套风控。

**未采用：** 首版直接部署 24 小时云服务；每个客户端维护独立状态；让 Agent 自行拼交易所 API 请求。

**代价与复议：** 会话关闭后本地组合监控停止。确有全天候需求时再引入常驻调度器，但必须共享同一账本与执行权。多机部署前重新评估存储一致性。

## ADR-002：研究能力与交易写权限分离

**决定：** 研究角色只访问数据和必要账户摘要；密钥只供受控执行适配器使用，后端不暴露绕过风控的原始 OKX 写入工具。

**理由：** 外部内容、工具结果和模型推断不构成资金操作授权。能力分离使研究错误难以直接变成订单。

**未采用：** 用提示词、Skills 说明或 MCP 工具隐藏单独当作资金保护；让研究 Agent 持有完整 API Key 并自觉遵守规则。

**代价与复议：** 需要明确的会话和凭证边界；同一操作系统身份下的恶意进程仍可能读取本机凭据，不能声称实现系统级隔离。

## ADR-003：独立研究、反方质询、主控综合

**决定：** 市场结构、项目事件、量化检验先独立阅读同一版本证据；再由反方审查，最后由主控汇总，并保留异议与缺失项。宿主按真实能力拉取和完成任务。

**理由：** 便于追溯研究路径和发现相互矛盾的假设。宿主 API 能力可能不同，因此必须记录实际并行、串行降级或不可用状态。

**未采用：** 多数票放行；模型自报胜率；假定 MCP 服务天然能启动 Codex / Claude Code 子 Agent；无授权情况下另购模型 API。

**代价与复议：** 多角色带来时间和调用成本，效果要用复盘数据检验。若角色无可验证增益，可缩减角色，但不删除证据与反方审查边界。

## ADR-004：版本化交易卡与可信人工确认

**决定：** 后端生成含入场、止盈止损、预算、风险、证据和异常权限的完整卡片；可信人工入口记录用户对卡片特定版本和哈希的决定。批准与提交分开。

**理由：** 用户批准的是具体可审阅交易，不是聊天中的模糊意图。保护与异常权限在下单前明确，才能在成交后按已授权规则恢复。

**未采用：** 模型调用 `approve` 并自称用户同意；一次授权未来所有交易；先开仓再讨论止损；参数变更沿用旧批准。

**代价与复议：** 需要可靠的真人交互适配器。如果客户端不能可信传递确认，就通过独立本机入口确认；未建立此边界时保持只读。

## ADR-005：单执行权、持久意图和交易所对账

**决定：** SQLite 保存批准、预留、意图、子动作 ID、风险事件和状态。提交前在本地事务内原子预留，事务提交后才调用交易所。所有客户端共享一个执行者和账本。

**理由：** 解决双客户端竞争、重启恢复、未知提交和重复入场。交易所与本地库没有跨系统事务，对账是必需流程。

**未采用：** 请求超时后直接重试下单；用内存锁作为唯一并发保护；把交易所 HTTP 返回视作最终成交；数据库不可写时无日志下单。

**代价与复议：** 本机单写入者限制水平扩展；以后多机部署须设计分布式执行权和强一致存储，不可简单复制 SQLite 文件。

## ADR-006：借助 OKX 官方工具，产品语义由本项目核验

**决定：** 行情和订单适配器优先复用 OKX Agent Trade Kit / Agent Skills 已核实的能力；本项目负责站点、demo/live、现货与 USDT 永续、合约面值、精度、成本及账户模式的实际校验。

**理由：** 避免重写交易所签名及基础请求；官方工具并不自动完成本项目的风控和批准语义。

**未采用：** 将原始官方下单工具直接暴露给研究 Agent；把“文档说支持”当作当前账户和产品已经通过能力测试。

**代价与复议：** 上游版本和地区支持可能变化。接入时固定版本、审查许可证与接口，按真实 demo 结果调整适配器；不支持的能力阻断对应交易。

## ADR-007：历史验证、模拟闭环、人工准入依次完成

**决定：** 策略和检验门槛先版本化，纳入费用及滑点、样本外检验；随后在真实 OKX 模拟环境跑通批准、下单、成交、保护、异常和恢复；最后由用户独立决定是否启用实盘。

**理由：** 研究想法、历史结果、模拟执行质量和实盘授权是不同证据。尤其短周期合约策略必须计算真实交易成本和执行限制。

**未采用：** 只看模型分析就实盘；本地假订单当作交易所模拟验收；模拟完成自动赋予实盘权限。

**代价与复议：** 准备时间较长；任何验证缺项都保持实盘关闭。盈利不被保证，表现随市场变化需持续复盘。

## ADR-008：手动运行与交易所原生保护

**决定：** 首版由用户手动运行，关闭前展示未成交订单、仓位和交易所确认的保护。不能依赖客户端离线后仍执行本地定时退出或组合止损。

**理由：** 用户当前工作方式是手动开启 Codex / Claude Code。运行边界必须与实际进程生命周期一致。

**未采用：** 把普通交易所止损宣传为全天候组合亏损熔断；没有常驻服务却承诺离线时间退出。

**代价与复议：** 组合阈值在离线期间可能延迟发现。需要更强实时性时，再开发并验证常驻监控及故障告警。

## ADR-009：哲学文本用于交易纪律

**决定：** 《德道经》的“知止”、承认未知与克制只用于研究提问、风险提醒和复盘纪律；引用与现代解释分开记录。

**理由：** 它能帮助团队保持审慎的操作流程，但不能替代价格数据、统计验证或订单对账。

**未采用：** 将古籍文字编码成未经检验的买卖信号，或称其能预知市场。

**代价与复议：** 文案和研究报告需标明这是纪律框架，不宣称来源版本已获学术定论。
