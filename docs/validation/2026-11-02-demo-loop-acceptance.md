# OKX demo 闭环验收（第一部分，2026-11-02）

证据类型：**真实 OKX global 模拟账户上的下单闭环**，经 `npm run demo:run`。策略为"管道验证"（`pipeline-test` v1，非交易策略），只验证出卡、否决窗、下单、保护与对账链路，不构成任何策略验证或实盘准入。记录只含状态，不含金额、账户标识或交易所订单号。

## 已验证

| 步骤 | 结果 |
| --- | --- |
| 风险配置与常设授权（ADR-012） | 用户本人经 Windows Hello 确认，两项分别为 confirmed / active（第一次真人确认） |
| 本机否决窗 | 窗口显示内容的哈希与卡片一致后才开始计时；用户未操作，窗口结束后后端核对授权与限额并记录批准 |
| 执行意图 | 批准被消费为唯一意图，入场、初始止损、移动止损的客户订单号固定 |

| 保护 | 按实际持有量（扣除以 BTC 计的手续费、按最小数量取整）挂出初始止损条件单与冻结回调价距的移动止损单，均被受理 |
| 对账 | 成交后对账无阻断；`status` 显示入场 filled、初始止损 live、移动止损 live |
| 限额 | 持仓期间再运行一轮，编卡即被风控拦下（`entry.spot_budget`、`entry.spot_plan_loss`），未进入否决窗、未下单 |

## 验收过程中由真实运行发现并修复的问题

均先补测试再修复，期间没有发出任何订单：

1. 账户快照只有 30 秒有效期，行情与账户读取后读取授权即失败并导致崩溃 → 授权读取失败按"无有效授权"处理，并在提交、显示、结算前刷新会话（`ba1152b`）。
2. 否决窗在自己的数据库事务内读取授权，而真实会话读取快照需要开启事务，嵌套失败使所有卡片显示为"无授权" → 授权在事务外读取，加回归测试（`a676363`）。
3. 本机时钟比 OKX 慢约 4.5 秒，报价时间戳被当作"来自未来"而在提交前重检时判为过期 → 允许最多 10 秒的交易所时钟领先；卡片过期且从未发单的意图释放占用；先打开下单连接再取报价（`2f3704e`）。
4. 否决窗脚本中的中文在 Windows PowerShell 5.1 下乱码 → 脚本只含 ASCII，文字以 UTF-8 数据传入，并以显示内容哈希校验（`661c863`）。
